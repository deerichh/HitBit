# HitBit

HitBit is a household (HIT) and business (BIT) inventory tracker.

- **HIT** — a household list with quantities, pars, expiry dates, a
  shopping list with sale prices and sources, a meal planner, and
  receipt scans that read a photo and propose the items on it.
- **BIT** — inventory for one or more businesses: counts by category,
  par levels, stock events, requisitions with a preparer / approver
  sign-off, manifest imports, and (for shops that use one) POS sync.

## First launch

HitBit starts with a short setup questionnaire: it asks about your
household and, for each business, its type and how it orders stock.
Nothing is pre-seeded with anyone else's data. A new user starts
clean and enters or uploads their own info.

Sample data is available for a first look: a generic ice-cream shop
("The Daily Scoop") with a year of simulated analytics. It loads only
when no business exists yet, through `importSampleData` in
`server/src/actions.ts`, and can be cleared from inside the app.

## Requisitions

A business that orders by requisition gets a Requisition tab instead
of the Order Email tab. The flow is:

1. An inventory check finishes; items at or below par land on a
   requisition form for review.
2. A preparer signs (typed initials render in cursive) and an
   approver — a different person — signs.
3. The form is saved with the requisition and can be downloaded as a
   PDF or emailed to the supplier (the recipient address is typed
   per send, not stored).

The PDF form is generated by the app (`server/src/reqFormTemplate.ts`)
— it is a plain generic requisition form, not any organisation's
official form. A filled-in form can also be scanned back in (PDF or
photo) and matched against the business's inventory by item number,
then name.

Division is free text the user sets. There are no back orders: items
not received carry to the next requisition badged "Resubmitted".

## Development

```sh
bun install
bun run typecheck   # client + server
bun run build       # server bundle, then client bundle
```

- Client: React + Tailwind in `client/` (`client/src/`, entry
  `client/build.mjs`).
- Server: actions in `server/src/actions.ts`, schema in
  `server/src/schema.ts`, SQLite via Drizzle.
- Migrations: `drizzle/` (numbered `0001`–`0039`, with
  `drizzle/meta/_journal.json`). Keep the order and the journal
  consistent; never renumber a shipped migration.

## Configuration

- **Household sheet (optional):** the HIT list can sync with a Google
  Sheet. Set `SPREADSHEET_ID` in `server/src/actions.ts` to your own
  sheet's ID. Never commit a real sheet ID, API key, token, or other
  secret — the template ships with the value blank.
- **Receipt scans** are read automatically while the Shopping List is
  open; nothing is added to inventory until the user confirms.
- **POS sync** is per-business and daily, never real-time. Secrets
  stay server-side and masked.

## Notes for a public repo

- This copy contains no user data: no database file, no household or
  business records, no receipt photos, no personal identifiers.
- `package.json` lists `@hatch/space-sdk` as a `file:` dependency on

  you set the project up elsewhere.
